# Data and retrieval

Respect current scope in `../../AGENTS.md`; this skill does not authorize implementation, model calls or publication. Read `../../dataset/02-dataset-guide.md` and the relevant scenario in `../../dataset/03-evaluation-queries.md`. Detailed design, source citations, tool contracts and acceptance checks live in `../../agent-memory/retrieval-research.md`; shared knowledge/privacy semantics are in `../../agent-memory/memory-research.md`.

Use full structured records for exact totals, rankings, deadline calculations and eligibility. Top-k prose retrieval cannot establish a complete fleet answer. The current recommendation is SQLite exact facts + shared correction authority + direct report/rule joins + deterministic section splitting and FTS5/BM25. Keep authority independent of search. Historical MiniLM results in `../../agent-memory/retrieval-experiments.md` are preserved evidence and **ineligible for integration** under the user's exclusive model policy; do not load another embedding or reranking model.

This retrieval strategy is **provisional and replaceable**, pending user review of actual source/storage/query traces. Read [operating contract](../../agent-memory/retrieval-operating-contract.md), [backend API contract](../../agent-memory/backend-api-contract.md) and [selective memory loading](../../agent-memory/long-term-memory-loading-decision.md). Inject the versioned `RetrievalProvider`; only the composition root selects its factory. Q&A, memory and UI must use typed queries, `ResultSet`/`EvidenceRef`, coverage and revisions, never SQLite tables, FTS details or ingestion layout. A replacement-provider contract test must preserve those behaviors.

Expose four compact model capabilities: `read_context`, `query_records`, `read_evidence`, `write_knowledge`. Compile the allowlisted general record-query algebra with bound values and deterministic domain derivations; never accept model SQL, arbitrary tables/paths/functions or a hidden scenario-specific answer router. Separate read-only record access from scoped memory and authority writes. Presentation pagination never limits aggregate input.

Read `../../agent-memory/model-policy.md` for current transport and quotas. Every copilot model operation must use **Gemma 4 31B Instruct only**: temporarily `gemma-4-31b-it` through `https://generativelanguage.googleapis.com/v1beta/openai/`. Existing generation/clean-JSON smoke evidence is in `../../agent-memory/google-gemma-verification.json`; it does not prove schema enforcement or retrieval/answer accuracy. Keep local schema/evidence validation and bounded repair. All app layers share the user-supplied maximum **30 RPM**; research calls require separate coordinator authorization. Never expose credentials or silently change model/provider.

Import every supplied same-format dataset root through one validated path. Discover assets, types, areas and linked reports dynamically. Preserve originals, source revision/license, hashes, JSONL line/field pointers and Markdown section/spans. Same ID with changed content is a version conflict; identical reimport is idempotent. Missing joins/reports and unsupported rules must appear in coverage, never disappear as zero.

Apply accepted shared corrections **before** every calculation/visual. Keep raw values, author/time/reason, validity/scope, supersession and conflicts. Ordinary notes are attributed claims, not corrections. Follow manual inheritance; a type/equipment-specific user rule changes only that predicate/scope and remains distinct from the manual. Unknown types do not inherit a guessed production threshold.

Production uses effective wellhead minus ambient temperature and the applicable manual. Downtime is seven days per observed non-producing inspection; missed inspections add zero, repair hours are separate. Repair costs use start date. Pin reference date, bounds, time basis, exact-decimal handling and tie policy; never silently use machine-now. Planned completion is not completed work.

Follow `maintenance.report_file`; filenames vary. Extract report facts deterministically first, retaining exact original spans and approximation/status/negation. Parse narrative and compliance tables independently; conflicts stay visible. Summaries are derived aids. Optional **Gemma-only** query expansion or ambiguous-prose extraction is a proposed, unmeasured extension until matched tests justify adoption. Bound calls/context, preserve exact filters and complete enumeration, verify extracted source spans locally, and retain unknowns; expansion/extraction cannot silently make an incomplete aggregate complete. Repair completion is not containment; cleanup is not passing agency verification.

Return immutable `ResultSet` and `EvidenceRef` objects with one dataset/knowledge revision, units, date semantics, rule/formula references, complete membership lineage and evaluated/unknown coverage. All UI blocks read the same factual data; the LLM explains it. A committed correction invalidates dependent answers/visuals; later users require at least its revision. Scope private lookups before retrieval, and expose only minimal attributed domain corrections rather than private chat.

Enforce the user's **5K content budget: 2K long-term private+shared TOTAL, 1K summary+historical dialogue, 2K fresh evidence**. Long-term loading is always private capsule/index600 + shared header/index200, with relevant private400 + shared800 selected within2K. Fresh evidence proposes results600 + rules650 + report spans550 + coverage200. Full records/chart arrays/manifests stay server-side; new fetches replace excerpts inside2K. Do not relabel source prose or old dialogue as overhead/memory to evade caps. Count persona/tools/current request/output/framing separately; disclose estimates versus exact compatible-request Gemma counts. Required evidence that cannot fit means a supported partial answer or clarification, not a larger hidden prompt.

Use at most two evidence rounds and eight read calls initially; normal model flow is planner plus composer, at most one optional evidence assistance and one formatting repair (four foreground attempts including provider retries). These are proposed bounds to validate, not measured optimal settings. SQL deadline/resource admission, source-span checks and explicit unknown coverage remain necessary even with valid JSON.

Provide detailed source-to-storage inspection: imported source/keys/counts, enrichment and effective values, query plan/tables/filters, selected versus omitted evidence and concise row previews. Admin diagnostics require explicit enabled mode and the server-validated capability shared with memory endpoints; a user picker/role is insufficient. Keep normal evidence viewer authorization separate, paginate previews, and expose no secrets, arbitrary SQL or complete-table browser dumps.
