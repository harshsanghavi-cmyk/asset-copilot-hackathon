# Replaceable ingestion/retrieval candidate and transparent viewer

17 Oct 2026. Main implementation was expressly authorized for this worker's owned ingestion/retrieval/viewer paths; **the user has not approved this candidate as the final retrieval strategy**. No model API calls, alternative models, credentials, raw-data changes, new Codex sessions or publication were performed by this worker.

## Implemented boundary

`backend/retrieval/contracts.py` defines the injected `RetrievalProvider` Protocol and `AuthoritySnapshot`. Q&A consumes `catalog`, `query(plan, context, authority)`, `search` and `evidence`; only the composition root imports `create_provider`. It receives typed plans and immutable result/evidence metadata, not SQL or directory internals. The backend owner agreed this seam and owns canonical memory, identity, authority writes, provider configuration and all live Gemma calls.

The current SQLite/FTS candidate can be replaced without changing chat/memory. Accepted runtime corrections, scoped rules and shared claims arrive through a canonical snapshot. This adapter never commits memory or treats an ordinary note as a correction. `GemmaEnricher` is an injectable interface only: no ingestion or viewer method invokes it, and diagnostics explicitly show `not_run`.

## Source ingestion and storage

`backend/ingestion/` streams bounded JSONL records, preserves original canonical JSON/source line/hash, loads normalized directories/assets/equipment/inspections/jobs/regulator events/notes, validates asset associations/joins/report links and exposes import issues. Duplicate identical roots do not duplicate records; conflicting IDs remain issues instead of silent overwrites. Original files are untouched. Markdown sections/chunks retain exact UTF-8 byte ranges and deterministic tags. Production thresholds are parsed from applicable manuals; unknown types stay unknown. Formal supported source spill corrections form a baseline overlay; cross-asset or missing targets are quarantined.

The verified sample index has **2,516 sources, 200 assets, 15 users, 39,567 inspections, 5,665 maintenance records, 90 regulator events, 141 notes, 56 baseline corrections, 1,094 equipment entries, 15,187 chunks, two parsed production rules and zero import issues**. There are **1,232 containment assertions**, preserving narrative/table repetitions for the 616 spill reports; this is not a claim of 1,232 independent incidents. The successful measured build took **27.191 seconds** in this run. Reference source revision is the pinned dataset commit in `docs/dataset-source.json`; the index also records its own content-manifest revision.

## Queries, evidence and fixes

Allowed public metrics cover records/count, latest status, temperature series, real spills, downtime, spill counts/volume, recorded maintenance cost, corrective counts/RCA, containment and supported incident compliance. Plans compile to parameterized application templates over effective fields; no raw SQL/files/network/extension functions are accepted. Read-only/query-only connections, authorizer restrictions, page/search bounds and cancellation budgets are active. Physical table/SQL details are exposed only through the explicit admin diagnostic router.

All calculations precede display pagination. Reviewer-identified bugs were corrected and regressed: collection-specific count semantics, full-population unknowns outside page one, null required volume, cross-asset correction activation, typed returned columns for temperature/map bindings, asset-only RCA grouping with equipment filter, known-complete area×month zero cells and `only_breaches` filtering. Indexed evidence handles replace full-record-store citation scans. Aggregate lineage uses durable derived manifests with paginated member access and source/snapshot checks; the hot registry remains bounded. Old source versions are not magically reconstructed after an index-source revision changes: stale manifests explicitly fail, while published answer retention belongs to the backend's durable answer store.

The deterministic `compliance` metric reads the supplied SOP protocol rows/class boundaries and joins effective spills, report facts and all related regulator events. It computes SR-01 written-notice, SR-02 containment, SR-03 passing-agency-verification and RC-04 NOV-response dates/statuses. It distinguishes late/closed, missing-record possibility, pending/not-due and unknown; it does **not** claim an exhaustive field-safety/legal audit. RCA, annual test evidence and planned-work notes use separate existing queries/evidence. Q9's actual June duties and Q13's corrected 5.4-bbl incident/24-hour reporting/23-Nov verification were deterministically checked; this is not a generated-answer evaluation.

Lexical search returns ranked report/source spans, asset/path/excerpt and honest selected/omitted coverage. The user's exact crude-oil report request is tested to invoke FTS/report search rather than status SQL. It does not establish a complete matching fleet list or independent truth of the report wording. Query expansion and LLM fact extraction remain not run.

## Viewer and actual review artifacts

`frontend/src/retrieval-viewer/` exports `RetrievalViewer` / `AdminViewer` with `baseAPI`, `initialTab`, `initialAssetId` and optional `localAdmin`. The UI owner mounts app/nav/admin HTML and owns all global theme/server files. Viewer tabs expose folder→store mappings, cardinalities/relations, bounded source preview, parsed/original/effective records, chunks, enrichment method/version/status, actual query traces, selected/omitted evidence, errors/unknowns and canonical memory admin APIs. No whole dataset arrays are loaded in the browser.

The main query inspector clearly separates **report-text search** from the **manual typed builder**. Free-text intent is not silently treated as a manual/default status query. Neither button invokes Gemma or hides provider errors. A local admin capability is required, independent of chat-user identity. The separate admin proxy keeps its token server-side; this worker does not read that token. The UI worker's `WELL-0001-WALKTHROUGH.md` is the immediate executed walkthrough artifact and remains their file after ownership transfer.

Read `experiments/05-retrieval-viewer/README.md` for the actual browser URL, step-by-step review and repeat commands. Screenshots live there, never in the coordinator's flat `diagrams/` folder. The source/body evidence shows actual data, with deterministic/model-not-run labels.

## Reference session inspection

Located the supplied reference session by filename. Read JSONL line-by-line in bounded windows, capped each line at 128 KiB, skipped oversize records, and printed only selected user-message text excluding secret-related content. Never loaded a complete transcript into memory, resumed a Codex process or spawned another session. Relevant requirements were concrete tool-to-collection mappings/examples, full current records versus history, independent batch context enrichment and avoiding whole-document model prompts. Those inspection principles informed this viewer; the other project's domain collections were not copied into the well schema.
