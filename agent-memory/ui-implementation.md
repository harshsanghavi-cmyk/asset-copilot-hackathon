Streaming/loading/error/empty/cancel/retry states are implemented. Plain source-free responses render without an empty dashboard or false evidence badge; evidence-only responses retain a compact source drawer. No fake live greeting or sample substitution is used.

## Runtime and interface boundary

`frontend/server/` is the authorized minimal TS CopilotKit companion. Request-scoped HttpAgent forwards X-User-Id/X-Session-Id to Python `/api/agent`; it has no provider credential. Runners are isolated per user/session, capped at24 by default and evicted after10 idle minutes. Active requests cannot be evicted; all-active capacity returns503. Durable history is backend-owned and survives runner recreation.

The frontend adapter uses GET/users, scoped session list/create/load/rename/delete and `/sessions/{id}/messages`. Error-history messages accept `client_message_id`, `error_code`, `error_message`; stable client IDs and `forwardedProps.retry_of_user_message_id` preserve retry identity. The backend owner implemented owner-scoped legacy run:user aliases and virtual durable failed-assistant records. Empty profile catalogs disable live submission visibly. Health `model_availability=paused_for_diagnosis` or `model_generation_enabled=false` produces an explicit Google Model under repair banner, disables send/retry and preserves history/admin without loading/stream spinners; no automatic probes/retries occur. Actual desktop/mobile pause-state checks pass. These client headers are a prototype identity boundary, not SSO.

The dedicated admin page invokes an allowlisted `/api/local-admin` proxy. Only that explicit diagnostic route privately reads `runtime/admin-token` and forwards the capability server-side; the browser never receives it. Missing diagnostic headers/non-loopback browser provenance and chat/session paths are rejected. Actual boundary checks return403/403/200 for missing capability, disallowed chat path and authorized memory read. The real admin browser has no token field or error alert. This developer service must not be publicly exposed as production access control.

The retrieval owner exclusively owns `frontend/src/retrieval-viewer/`. UI hosts its public entry through ViewerHost; no internals were edited. Admin hash wiring supports `/admin.html#walkthrough?asset_id=WELL-0001` via generic bounded `initialAssetId` and `initialTab=walkthrough`; GET /retrieval/walkthrough is allowlisted in the explicit admin proxy; actual API200 and browser deep link are now verified, including selecting WELL-0002 and reloading the WELL-0001 deep link. The page shows the real custom report, correction and containment span without model generation. Root's reported ignored-text/manual-query bug was forwarded to that owner for explicit manual-plan versus report-search separation. Connected chat itself has no fallback status/sample answer.
